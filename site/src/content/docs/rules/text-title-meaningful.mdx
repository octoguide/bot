A title is the first -- and often only -- part of an issue or pull request that other contributors read.
Titles left as a template's default, or that don't say anything beyond it, make the work harder to find and triage.

This rule reports two kinds of unhelpful titles:

- Titles still set to the default title of the template they were created from
- Titles that don't contain any word beyond the ones already in the repository name and template title

## Default Template Titles

Issue templates can pre-fill a title for issues created from them.
For example, an [issue form](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms) might contain:

```yml title=".github/ISSUE_TEMPLATE/01-bug.yml"
name: 🐛 Bug
title: "🐛 Bug: <short description of the bug>"
```

An issue created from that template starts out titled `🐛 Bug: <short description of the bug>`.
This rule reports if that title is left as-is, or cut down to just its `🐛 Bug:` prefix.

Pull request templates can't pre-fill a title, so only the informativeness check runs on pull requests.

## Informative Titles

The informativeness check uses [`are-docs-informative`](https://github.com/JoshuaKGoldberg/are-docs-informative) to see whether a title contains at least one word that isn't already implied by the repository name or the title of the template the entity was created from.

For a repository named `octoguide` using the template above:

```plaintext
🐛 Bug: the bug          ❌ adds nothing beyond "bug" from the template title
octoguide                ❌ adds nothing beyond the repository name
🐛 Bug: reports posted twice on re-runs  ✅
```
